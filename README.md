# DocScan

Фото паспорта или ID-карты → распознавание MRZ прямо в браузере → анкета для шенгенской визы,
проверенная и заполненная в PDF. Backend отсутствует: фото, OCR-модели и готовый PDF никогда не
покидают устройство.

## Запуск

```bash
npm install
sh scripts/fetch_assets.sh   # модели OCR и WASM-рантайм — большие бинарники, не в git
npm run dev
```

Другие команды: `npm test` (юнит-тесты), `npm run build` (проверка типов + сборка), `npm run lint`.

Форматы фото: JPG, PNG, WebP и HEIC. HEIC с iPhone конвертируется в JPEG прямо в браузере
библиотекой `heic-to` (libheif, LGPL-3.0); её ~3 МБ загружаются, только когда пришёл HEIC-файл.

`scripts/fetch_assets.sh` идемпотентен: уже скачанные файлы он не трогает, можно запускать
повторно.

## Деплой

Пошаговая инструкция для Railway: [docs/deploy-railway.md](docs/deploy-railway.md). Для любого
другого Docker-хостинга подойдут те же `Dockerfile` и `Caddyfile`.

Задеплоенный сайт закрыт страницей входа (`public/login.html`): Caddy пускает дальше только с cookie, ключ которой есть
в переменной `AUTH_KEYS`. Ключ для email и пароля печатает `sh scripts/auth-key.sh`; без `AUTH_KEYS` контейнер не
запустится. `npm run dev` вход не проверяет.

## Как добавить бланк

Где что лежит:

- `blanks-src/` — чистые Word-бланки с метками, исходники форм. Сайт их не отдаёт.
- `public/blanks/` — готовые PDF-формы, их заполняет `src/lib/fill.ts`.
- `src/lib/blanks/` — описания: какое поле формы что печатает. Для формы из Word это `<имя>.fields.ts`, его пишет
  `make-form`. У чужих PDF-форм (`pl-d.ts`, `bg.ts`) соответствие записано вручную по подписям бланка.
- `scripts/blanks/` — `docx.py` (просмотр, очистка, проходы) и его самопроверка `docx-selfcheck.py`, `find-text.js`,
  `make-form.mjs`, `clean-pdf.mjs`.

**Файлы с персональными данными никогда не коммитятся и не копируются в проект**: образцы клиентов, их распаковки,
`removed.txt`, скрипт проверки утечек и его вывод. Образец лежит во временной папке вне репозитория, скрипты — в другой
папке и получают путь аргументом, Python запускается с `-I`. Образец смотрят только через `docx.py dump`, его страницы
не рендерятся в картинки: рендерятся только чистые бланки и PDF-формы. Значения образцов не попадают ни в код, ни в
тесты, ни в сообщения коммитов.

Метки в чистом Word-бланке; метка — весь текст своего прогона:

- `{{cell:WxH}}` — текстовое поле W × H pt. `cell` — ключ печати из `PRINT_KEYS` (`src/lib/print.ts`) или два ключа через
  плюс (`address+email`). Левый верхний угол поля — у метки, на ¾ кегля её строки выше базовой линии. С высоты 26 pt поле
  многострочное: в поле ниже `fill.ts` всё равно пишет одну строку. Поле занимает свободную часть ячейки и не закрывает
  подпись бланка.
- `{{tick}}` — сразу после квадратика `☐` или `□` (у маркера-квадратика списка — в начале абзаца): флажок на этом
  квадратике. Ключи флажков — `${ChoiceKey}.${option}`, `means.${payer}.${option}` и `sponsorOther` (тип `Blank` в
  `src/lib/questionnaire.ts`).

Шаги:

1. `python3 -I scripts/blanks/docx.py dump <образец.docx>` — абзацы с номерами прогонов `[r<номер>]`. Текст
   маскируется: слово с `@`, тремя цифрами подряд или двумя заглавными подряд печатается как `Aa`, `Бб`, `9`. Квадратики,
   фигуры и маркеры списка видны как `[☐]`, `[shape …]`, `[bullet …]`; путь к файлу вне документа (связанная картинка,
   ссылка) маскируется весь. В конце — картинки (размер, где стоят), части пакета и счётчики правок, полей, ссылок,
   надписей и авторов правок. Колонтитулы и сноски печатаются тоже. Строка `== apply refuses` называет части, с которыми
   `apply` не работает: примечания, их авторы (`word/people.xml`) и стандартные блоки (`word/glossary/`) — их удаляют в
   Word и сохраняют образец заново.
2. Правки — `edits.json` по номерам из `dump`, виды правок и пример в начале `docx.py`: `replace`, `clear`, `box` (для
   прогона с несколькими квадратиками — список меток по порядку), `add` (с `r` и `after` — внутри прогона сразу после
   его текста `after`, когда подпись и следующий заголовок напечатаны одним прогоном), `para`, `ind` и список `media`.
   `ind` чуть ослабляет отступ строки, заполненной до края: иначе метки прохода A сталкивают её последнее слово на
   следующую строку и поле встаёт не там. Прибавка меньше следующего слова, чтобы B сохранил переносы (сверить рендером).
   Если образец не сохранялся в Word (вывод конвертера) и в `docProps/app.xml` нет `<Pages>`, число страниц даёт
   `"pages"` в `edits.json`: по странице на раздел, начинающийся с новой страницы; своё число Word `apply` не меняет.
3. `python3 -I scripts/blanks/docx.py apply <образец.docx> <edits.json> blanks-src/<имя>.docx --removed <папка>/removed.txt`.
   Стираются значения клиента (метками или пустым местом), отметки над квадратиками, ссылки `mailto:` вокруг значений,
   автор, редактор и прочие сведения в `docProps`, имена и инициалы авторов правок во всех частях, пользовательские
   свойства и `customXml`, альтернативный текст и имена картинок и фигур и миниатюра. Значения в колонтитулах и сносках правятся так же (`"part": "word/header1.xml"`). Из картинок остаются
   только эмблемы и логотипы бланка: фото, подпись, печать и всё личное перечисляются в `media`, при сомнении картинка
   удаляется. Всё стёртое пишется в `removed.txt`, он остаётся во временной папке.
4. `dump` чистого бланка: замаскированными остались только напечатанные слова бланка, такие же строки есть в другом
   образце того же бланка.
5. `node scripts/blanks/make-form.mjs blanks-src/<имя>.docx public/blanks/<имя>.pdf src/lib/blanks/<имя>.fields.ts`.
   Внутри: `docx.py passes` пишет проход A (метки моноширинным шрифтом шириной 1 %: 1 pt среди текста, кеглем строки, если
   метка в абзаце одна) и проход B (текста меток нет), LibreOffice переводит оба в PDF, `find-text.js` находит метки и
   квадратики, поля ставятся на страницы B, `clean-pdf.mjs` убирает сведения о документе и XMP. Сборка останавливается,
   если в `docProps/app.xml` нет `<Pages>` или число страниц в Word, A и B разное, если квадратиков на странице A и B
   разное число или они сдвинулись по вертикали больше чем на 1 pt (по горизонтали — больше чем на ширину меток левее в
   строке и ещё 1 pt), если метки, записанной в A, нет на его страницах (или там есть лишняя), если имя метки
   повторяется, если у флажка нет квадратика слева или два флажка на одном квадратике.
6. Проверка рендером: `osascript -l JavaScript scripts/render-pdf-page.js <файл.pdf> <папка> 0 1 2`. Пустая форма: те же
   страницы и пункты, рамки и логотипы на месте, меток не видно. Заполненная образцом: `PDF_OUT=<папка> npx vitest run
   src/lib/fill.test.ts` пишет заполненные формы; значения в своих ячейках, галочки в нужных квадратиках.
7. Проверка утечек перед коммитом: одноразовый локальный скрипт вне проекта ищет значения образцов и строки
   `removed.txt` во всех частях чистого `.docx`, в тексте страниц и распакованных потоках PDF-формы. Находок быть не должно.
8. Анкета — строка в `QUESTIONNAIRES` (`src/lib/questionnaire.ts`): `fromFields("blanks/<имя>.pdf", <описание>)`, нумерация
   пунктов (`NUMBERING_A`, `NUMBERING_B` или своя), страна и предустановки. Города подачи страны — в `src/lib/cities.ts`:
   русское название для списка (`ru`) и английское для печати (`print`). Общие тесты `fill.test.ts` и `blank-files.test.ts`
   заполняют каждую форму образцом и проверяют, что пустая форма без данных и метаданных.

После любой правки `docx.py` — `python3 -I scripts/blanks/docx-selfcheck.py`. Он собирает Word-файл с выдуманными
значениями и проверяет, что `dump` их маскирует (и значение, разбитое на прогоны ссылки, кода поля или удалённой правки,
и путь связанной картинки), а `apply` и `passes` делают то, что описано в шагах. Последняя строка должна быть
`docx.py self-check: all good`.

LibreOffice (`brew install --cask libreoffice`) и Python 3 нужны только разработчику, чтобы собрать форму: сайт и тесты
работают с готовыми PDF. `soffice` берётся из `PATH` или из переменной `SOFFICE`.
