# DocScan

Фото паспорта или ID-карты → распознавание MRZ прямо в браузере → анкета для шенгенской визы,
проверенная и заполненная в PDF. Backend отсутствует: фото, OCR-модели и готовый PDF никогда не
покидают устройство.

## Запуск

```bash
npm install
sh scripts/fetch_assets.sh   # модели OCR и WASM-рантайм — большие бинарники, не в git
npm run dev
```

Другие команды: `npm test` (юнит-тесты), `npm run build` (проверка типов + сборка), `npm run lint`.

Форматы: JPG, PNG, WebP, HEIC и PDF. HEIC с iPhone конвертируется в JPEG прямо в браузере
библиотекой `heic-to` (libheif, LGPL-3.0); её ~3 МБ загружаются, только когда пришёл HEIC-файл.
PDF-скан (до 6 страниц) превращает в картинки `pdfjs-dist`, тоже в браузере и тоже только по требованию;
MRZ ищется на каждой странице по очереди.

Бронь гостиницы: в разделе «Приглашающая сторона», когда приглашает гостиница, кнопка «Загрузить бронь» принимает
подтверждение Booking.com на русском языке, скачанное в PDF. Распознавания здесь нет: `pdfText` (`src/lib/pdf.ts`)
берёт текст из самого файла, `parseBooking` (`src/lib/booking.ts`) находит в нём название, адрес, телефон и даты заезда и
выезда. Года в брони нет, его даёт день недели. Всё заполненное помечается «проверьте»: адрес бывает с кириллицей
(страна переводится на английский, город нет), а даты проживания не всегда равны датам поездки. Фото и скриншоты брони, другие
сайты и другие языки не читаются.

`scripts/fetch_assets.sh` идемпотентен: уже скачанные файлы он не качает заново, можно запускать
повторно. Каждый файл сверяется с контрольной суммой SHA-256, записанной в скрипте: модели и WASM исполняются в
браузере рядом с фото паспорта, поэтому подменённый или изменившийся на хостинге файл останавливает сборку. После
намеренного обновления версии суммы в скрипте меняют вручную.

Скрипт также патчит воркер PaddleOCR.js (`scripts/patch-ocr-worker.mjs`): MRZ читается только алфавитом MRZ и с запасным
вариантом каждого символа. `npm install` может вернуть исходный воркер, поэтому после него запускайте скрипт снова. Без
патча распознавание работает, но без этих вариантов.

## Замеры распознавания

Разбор MRZ проверяет `npm test`: `src/lib/eval.test.ts` портит синтетические строки выдуманных людей, итоги лежат в
снимке `src/lib/__snapshots__/`. Частоты ошибок там выдуманные: снимок сравнивает две версии разбора и ничего не говорит о
реальных фото. Если он изменился намеренно, обновите его через `npx vitest run src/lib/eval.test.ts -u`.

Реальные фото: папка **вне репозитория** с фотографиями и `truth.json` вида `{ "photo.jpg": ["строка 1 MRZ", "строка 2 MRZ"] }`.
`npm run dev`, открыть `/eval.html`, выбрать папку. Страница считает всё в браузере и показывает только итоги; в сборку она
не входит.

Каждое фото читается в 26 вариантах (`VARIANTS` в `src/eval.ts`): как есть, уменьшенное, пережатое, ч/б, как ксерокопия,
тёмное, размытое, с шумом, повёрнутое, с тенью и с бликом. Варианты делаются на лету и никуда не сохраняются; шум и углы
заданы числами, поэтому два замера отличаются только распознаванием. В таблице по строке на вариант: сколько фото не
распознано, сколько прочитано без единой ошибки и в каких полях ошибки. Столбец «неверно со значком MRZ» — неверно
прочитанные поля, показанные как подтверждённые: это число должно быть нулём. Три фото занимают около семи минут.
Замер запускают до и после любого изменения распознавания, пороги в `src/lib/ocr.ts` подобраны по нему.

## Деплой

Пошаговая инструкция для Railway: [docs/deploy-railway.md](docs/deploy-railway.md). Для любого
другого Docker-хостинга подойдут те же `Dockerfile` и `Caddyfile`.

Задеплоенный сайт закрыт страницей входа (`public/login.html`): Caddy пускает дальше только с cookie, ключ которой есть
в переменной `AUTH_KEYS`. Ключ для email и пароля печатает `sh scripts/auth-key.sh`; без `AUTH_KEYS` контейнер не
запустится. `npm run dev` вход не проверяет.

`Caddyfile` отдаёт Content-Security-Policy: страница загружает код и обращается по сети только к своему домену, так
что фото и данные анкеты некуда отправить, даже если зависимость окажется вредоносной. Новая библиотека, которой нужен
чужой домен, `eval` или `blob:`, под этой политикой молча не заработает: проверяйте сборку за локальным Caddy
(`caddy run` с этим `Caddyfile`), а не только `npm run dev`, где политики нет. Межсайтовую изоляцию (COOP/COEP) ради
многопоточного OCR не включать: файлы из кэша браузера, сохранённые без этих заголовков, перестают загружаться в
воркер, и распознавание ломается у всех, кто уже открывал сайт.

## Как добавить бланк

Где что лежит:

- `blanks-src/` — чистые Word-бланки с метками, исходники форм. Сайт их не отдаёт.
- `public/blanks/` — готовые PDF-формы, их заполняет `src/lib/fill.ts`.
- `src/lib/blanks/` — описания: какое поле формы что печатает. Для формы из Word это `<имя>.fields.ts`, его пишет
  `make-form`. У чужих PDF-форм (`pl-d.ts`, `bg.ts`) соответствие записано вручную по подписям бланка.
- `scripts/blanks/` — `docx.py` (просмотр, очистка, проходы) и его самопроверка `docx-selfcheck.py`, `find-text.js`,
  `make-form.mjs`, `clean-pdf.mjs`.

**Файлы с персональными данными никогда не коммитятся и не копируются в проект**: образцы клиентов, их распаковки,
`removed.txt`, скрипт проверки утечек и его вывод. Образец лежит во временной папке вне репозитория, скрипты — в другой
папке и получают путь аргументом, Python запускается с `-I`. Образец смотрят только через `docx.py dump`, его страницы
не рендерятся в картинки: рендерятся только чистые бланки и PDF-формы. Значения образцов не попадают ни в код, ни в
тесты, ни в сообщения коммитов.

Метки в чистом Word-бланке; метка — весь текст своего прогона:

- `{{cell:WxH}}` — текстовое поле W × H pt. `cell` — ключ печати из `PRINT_KEYS` (`src/lib/print.ts`) или два ключа через
  плюс (`address+email`). Левый верхний угол поля — у метки, на ¾ кегля её строки выше базовой линии. С высоты 26 pt поле
  многострочное: в поле ниже `fill.ts` всё равно пишет одну строку. Поле занимает свободную часть ячейки и не закрывает
  подпись бланка.
- `{{tick}}` — сразу после квадратика `☐` или `□` (у маркера-квадратика списка — в начале абзаца): флажок на этом
  квадратике. Ключи флажков — `${ChoiceKey}.${option}`, `means.${payer}.${option}` и `sponsorOther` (тип `Blank` в
  `src/lib/questionnaire.ts`).

Шаги:

1. `python3 -I scripts/blanks/docx.py dump <образец.docx>` — абзацы с номерами прогонов `[r<номер>]`. Текст
   маскируется: слово с `@`, тремя цифрами подряд или двумя заглавными подряд печатается как `Aa`, `Бб`, `9`. Квадратики,
   фигуры и маркеры списка видны как `[☐]`, `[shape …]`, `[bullet …]`; путь к файлу вне документа (связанная картинка,
   ссылка) маскируется весь. В конце — картинки (размер, где стоят), части пакета и счётчики правок, полей, ссылок,
   надписей и авторов правок. Колонтитулы и сноски печатаются тоже. Строка `== apply refuses` называет части, с которыми
   `apply` не работает: примечания, их авторы (`word/people.xml`) и стандартные блоки (`word/glossary/`) — их удаляют в
   Word и сохраняют образец заново.
2. Правки — `edits.json` по номерам из `dump`, виды правок и пример в начале `docx.py`: `replace`, `clear`, `box` (для
   прогона с несколькими квадратиками — список меток по порядку), `add` (с `r` и `after` — внутри прогона сразу после
   его текста `after`, когда подпись и следующий заголовок напечатаны одним прогоном; с `r` без `after` — в начале или
   в конце абзаца, но в формате прогона `r`: так возвращают квадратик, потерянный при конвертации бланка, —
   `"add": "□"` перед меткой флажка, в формате слов подписи), `para`, `ind`, `spacing`, `bullet`, `checkbox` и список
   `media`. `checkbox` — для поля-флажка Word (FORMCHECKBOX, в `dump` — `[chk]`): `r` — прогон начала поля, поле
   уходит целиком вместе с отметкой (`w:checked`, `w:default`, результат) и своим размером, на его месте — текстовый
   `☐` шрифтом и кеглем этого прогона, без жирного, разрядки и масштаба, и сразу за ним метка (`""` — без метки, например
   в колонке для служебных отметок). `"size"` (полупункты) задаёт другой кегль, если прогон мельче остальных квадратиков
   бланка: все квадратики формы одинаковые. Пока в бланке осталось
   хоть одно поле-флажок, `apply` останавливается. `dump` в строке `== counts` пишет, сколько флажков отмечено
   (`checked=`), но не какие: это выбор клиента. `bullet` с `{"position": 0}` — для абзаца-пункта списка, у маркера которого свой `w:position`: конвертер
   рисует такой маркер верхним индексом, квадратик выходит крошечным и выше строки; правка ставит его на строку в его
   кегле. Уровень списка общий, меняются все его пункты; правка задаёт только `position` (полупункты), с другим
   атрибутом или без `w:position` у уровня `apply` останавливается. `ind` чуть ослабляет отступ строки, заполненной до
   края: иначе метки прохода A сталкивают её последнее слово на следующую строку и поле встаёт не там. Прибавка меньше
   следующего слова, чтобы B сохранил переносы (сверить рендером). Им же ставят возвращённый квадратик внутрь колонки,
   вровень с её маркерами списка, когда отступ строки нулевой или отрицательный. `spacing` с `"lineRule": "atLeast"` —
   для строки с точной высотой меньше её текста, у которой конвертер срезает верх (у приподнятых слов строки — тоже);
   ниже на странице всё сдвигается вместе (сверить рендером, что страниц столько же). Оба задают только
   свои атрибуты (`ind`: left, right, start, end, firstLine, hanging; `spacing`: before, after, line, lineRule), с
   другим `apply` останавливается. `row` задаёт `w:trHeight` строки таблицы, в которой стоит абзац `p` (val в твипах,
   больше 0, hRule): поле в строке точной высоты, которому не хватает второй строки. Высоту берут у соседней строки,
   выше или ниже, с пустым местом (две правки `row`), тогда остальные строки не сдвигаются (сверить рендером). Одна
   запись — одна правка: с двумя видами (`ind` и `spacing` вместе) `apply` останавливается. Если образец не сохранялся в Word (вывод конвертера) и в `docProps/app.xml` нет
   `<Pages>`, число страниц даёт `"pages"` в `edits.json`: по странице на раздел, начинающийся с новой страницы. Если
   `<Pages>` от Word в образце есть, `apply` с `"pages"` останавливается.
3. `python3 -I scripts/blanks/docx.py apply <образец.docx> <edits.json> blanks-src/<имя>.docx --removed <папка>/removed.txt`.
   Стираются значения клиента (метками или пустым местом), отметки над квадратиками, ссылки `mailto:` вокруг значений,
   автор, редактор и прочие сведения в `docProps`, имена и инициалы авторов правок во всех частях, пользовательские
   свойства и `customXml`, альтернативный текст и имена картинок и фигур и миниатюра. Значения в колонтитулах и сносках правятся так же (`"part": "word/header1.xml"`). Из картинок остаются
   только эмблемы и логотипы бланка: фото, подпись, печать и всё личное перечисляются в `media`, при сомнении картинка
   удаляется. Всё стёртое пишется в `removed.txt`, он остаётся во временной папке.
4. `dump` чистого бланка: замаскированными остались только напечатанные слова бланка, такие же строки есть в другом
   образце того же бланка.
5. `node scripts/blanks/make-form.mjs blanks-src/<имя>.docx public/blanks/<имя>.pdf src/lib/blanks/<имя>.fields.ts`.
   Внутри: `docx.py passes` пишет проход A (метки моноширинным шрифтом шириной 1 %: 1 pt среди текста, кеглем строки, если
   метка в абзаце одна; такой абзац выравнивается влево, чтобы поле начиналось от края строки, а не с середины
   ячейки) и проход B (текста меток нет), LibreOffice переводит оба в PDF, `find-text.js` находит метки и
   квадратики, поля ставятся на страницы B, `clean-pdf.mjs` убирает сведения о документе и XMP. Сборка останавливается,
   если в `docProps/app.xml` нет `<Pages>` или число страниц в Word, A и B разное, если квадратиков на странице A и B
   разное число или они сдвинулись по вертикали больше чем на 1 pt (по горизонтали — больше чем на ширину меток левее в
   строке и ещё 1 pt), если метки, записанной в A, нет на его страницах (или там есть лишняя), если имя метки
   повторяется, если у флажка нет квадратика слева или два флажка на одном квадратике. Квадратик флажка — ближайший
   слева, не дальше своей ширины, по высоте заходящий в строку метки (от ¼ её кегля ниже базовой линии до ¾ выше):
   квадратик может быть приподнят или опущен (`w:position`, свой шрифт маркера списка), метка стоит на базовой линии.
6. Проверка рендером: `osascript -l JavaScript scripts/render-pdf-page.js <файл.pdf> <папка> 0 1 2`. Пустая форма: те же
   страницы и пункты, рамки и логотипы на месте, меток не видно. Заполненная выдуманными данными `SPECIMEN`: `PDF_OUT=<папка> npx vitest run
   src/lib/fill.test.ts` пишет заполненные формы; значения в своих ячейках, галочки в нужных квадратиках.
7. Проверка утечек перед коммитом: одноразовый локальный скрипт вне проекта ищет значения образцов и строки
   `removed.txt` во всех частях чистого `.docx`, в тексте страниц и распакованных потоках PDF-формы. Находок быть не должно.
8. Анкета — строка в `QUESTIONNAIRES` (`src/lib/questionnaire.ts`): `fromFields("blanks/<имя>.pdf", <описание>)`, нумерация
   пунктов (`NUMBERING_A`, `NUMBERING_B` или своя), страна и предустановки. Города подачи страны — в `src/lib/cities.ts`:
   русское название для списка (`ru`) и английское для печати (`print`). Общие тесты `fill.test.ts` и `blank-files.test.ts`
   заполняют каждую форму выдуманными данными `SPECIMEN`, не образцом, и проверяют, что пустая форма без данных и
   метаданных.

Чужая PDF-форма (как `pl-d.pdf` и `bg.pdf`): `node scripts/blanks/clean-pdf.mjs <образец.pdf> public/blanks/<имя>.pdf`
очищает поля и убирает сведения о документе, XMP и пометки рецензента; поле, которое скрипт не умеет очищать (список,
подпись), его останавливает. Описание пишется вручную по подписям бланка, как `src/lib/blanks/pl-d.ts`, дальше —
проверка утечек (шаг 7), рендер (шаг 6) и анкета (шаг 8).

После любой правки `docx.py` — `python3 -I scripts/blanks/docx-selfcheck.py`. Он собирает Word-файл с выдуманными
значениями и проверяет, что `dump` их маскирует (и значение, разбитое на прогоны ссылки, кода поля или удалённой правки,
и путь связанной картинки), а `apply` и `passes` делают то, что описано в шагах. Последняя строка должна быть
`docx.py self-check: all good`.

После любой правки `make-form.mjs`, `find-text.js` или `docx.py passes` каждая Word-форма пересобирается из своего
`blanks-src/<имя>.docx` (шаг 5) и сравнивается с закоммиченной: имена, типы, страницы и прямоугольники виджетов те же,
`<имя>.fields.ts` не меняется.

LibreOffice (`brew install --cask libreoffice`) и Python 3 нужны только разработчику, чтобы собрать форму: сайт и тесты
работают с готовыми PDF. `soffice` берётся из `PATH` или из переменной `SOFFICE`.

VK Sans Display — корпоративный шрифт VK. Перед публичным деплоем проверьте условия его лицензии.
