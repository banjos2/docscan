# DocScan — дизайн

Дата: 2026-09-28

## Задача

Веб-страница: слева загружается фото документа (паспорт, ID-карта), из него считываются данные, справа они показываются в редактируемой форме. После одобрения данные вписываются в бланк шенгенской анкеты (Испания, `ANKETA.pdf`), готовый PDF можно посмотреть и скачать.

## Решения

| Вопрос | Решение |
|---|---|
| Где работает распознавание | В браузере. Бэкенда нет, фото не покидает устройство. |
| OCR | `@paddleocr/paddleocr-js` (официальный SDK PaddleOCR, PP-OCRv5 mobile det + `en_PP-OCRv5_mobile_rec`, onnxruntime-web, WASM). |
| Разбор MRZ | npm `mrz`: TD1/TD2/TD3, контрольные цифры, автокоррекция. |
| Набор полей | Пункты 1–16 из документа плюс все поля, заполненные в образце. |
| Заполнение PDF | `pdf-lib` впечатывает текст по координатам поверх чистого бланка. |
| Стек | Vite, React, TypeScript, Tailwind v4, shadcn/ui, токены дизайн-системы Graphite. Шрифт — VK Sans Display (400–700) вместо Geist и Onest. |

Отклонённые варианты: Tesseract.js (слабее на фото с телефона), Claude Vision API (фото уходит на сторонний сервер), Python-сервер с PassportEye или OmniMRZ (нужен хостинг, фото уходит с устройства), AcroForm-поля в бланке (больше кода при том же результате).

## Бланк

Чистый бланк получен из `ANKETA.pdf`: заполненные значения лежали в отдельном Form XObject `/Fm0` на каждой странице. Он удалён вместе со ссылками из ресурсов страниц, после чего объекты собраны сборщиком мусора. Файл лежит в `public/anketa-template.pdf`. Перед сохранением проверяется, что в нём не осталось текста персональных данных из образца.

Координаты полей сняты с образца (базовая линия, размер шрифта) и хранятся в `src/lib/layout.ts`. Координаты квадратиков `□` для галочек берутся из бланка. Галочка рисуется символом ✔ шрифта ZapfDingbats, как в образце.

## Экран

Два столбца от `lg`, на узком экране один столбец.

- **Шапка:** надпись `DOCSCAN` в стиле `display-title` (VK Sans Display, заглавные), над ней eyebrow «Шенгенская анкета» цвета `flame-ink`.
- **Слева:** плитка `bg-tile rounded-3xl` без рамки, drag-and-drop или выбор файла (`image/*`). После загрузки в плитке показываются превью, статус («Загружаю модель…», «Распознаю…») и кнопка «Заменить фото». Ошибка распознавания выводится в `Alert destructive` с текстом, что сделать («MRZ не найдена. Сфотографируйте страницу целиком, без бликов на нижних строках»).
- **Справа:** `Card` с двумя группами.
  - **«Из документа»:** пп. 1–16. У поля бейдж источника: `MRZ` (прочитано, контрольная цифра сошлась), `проверьте` (контрольная цифра не сошлась или значение найдено эвристикой) или `вручную`.
  - **«Поездка и контакты»:** вводится вручную.
- **Низ правой колонки:** кнопка `primary` «Одобрить и сформировать PDF». После нажатия появляются предпросмотр (`<iframe>` с blob-URL) и кнопка «Скачать PDF» (`anketa-<ФАМИЛИЯ>.pdf`).

Тема светлая или тёмная по `prefers-color-scheme`, переключателя нет.

## Поля

### Из документа

| П. | Поле | Источник |
|---|---|---|
| 1 | Фамилия | MRZ |
| 2 | Фамилия при рождении | по умолчанию = п. 1 |
| 3 | Имя | MRZ |
| 4 | Дата рождения | MRZ, `ДД-ММ-ГГГГ` |
| 5 | Место рождения | вручную |
| 6 | Страна рождения | по умолчанию = гражданство |
| 7 | Гражданство | MRZ (код → английское название заглавными через справочник `states` пакета `mrz`, `BLR` → `BELARUS`) |
| 7 | Гражданство при рождении | по умолчанию = гражданство |
| 8 | Пол | MRZ → галочка |
| 9 | Семейное положение | вручную, выбор из 7 вариантов бланка → галочка |
| 11 | Номер национального документа | MRZ, поле optional/personal number |
| 12 | Тип документа | по умолчанию «обычный паспорт» → галочка |
| 13 | Номер документа | MRZ |
| 14 | Дата выдачи | эвристика по всему тексту страницы, бейдж `проверьте`; иначе вручную |
| 15 | Действителен до | MRZ |
| 16 | Кем выдан (страна) | MRZ, код государства выдачи → название |

Эвристика для п. 14: из всего распознанного текста страницы достаются даты (`ДД.ММ.ГГГГ`, `ДД ММ ГГГГ`, `ДД MMM/MMM ГГ` и похожие), из них убираются дата рождения и срок действия. Если осталась ровно одна дата раньше срока действия, она подставляется.

### Поездка и контакты

Поля, заполненные в образце:

- п. 19: адрес (2 строки), e-mail, телефон;
- п. 20: проживает в другой стране, `Нет` или `Да` (по умолчанию `Нет`);
- п. 21: профессия;
- п. 23: цель поездки, выбор из вариантов бланка;
- п. 25: страна основного назначения;
- п. 26: страна первого въезда;
- п. 27: количество въездов (одно, два, много);
- п. 28: даты въезда и выезда;
- п. 29: отпечатки ранее, `Нет` или `Да`;
- п. 31: приглашающий или отель, его адрес (2 строки) и телефон;
- п. 33: кто платит (сам или спонсор); для спонсора поле «кто», которое вписывается в строку «иные (указать)»; средства — набор галочек соответствующей колонки;
- место и дата заполнения (стр. 4), дата по умолчанию сегодняшняя.

## Распознавание: поток данных

1. Файл → `ImageBitmap`.
2. `PaddleOCR.create({ textDetectionModelName: "PP-OCRv5_mobile_det", textRecognitionModelName: "en_PP-OCRv5_mobile_rec", worker: true, ortOptions: { backend: "wasm" } })`. Экземпляр создаётся один раз и переиспользуется. Распознаватель английский: словарь из ASCII с `<`, без иероглифов-двойников, вдвое легче стандартного. Модели — официальные ONNX-версии PaddlePaddle с Hugging Face, упакованные в `.tar` и лежащие в `public/models/`: серверы Baidu из сети разработки недоступны.
3. `predict(bitmap)` → строки `{ text, score, poly }`.
4. Нормализация MRZ-кандидатов: заглавные буквы; `«`, `く`, `‹`, пробелы и прочие символы вне `[A-Z0-9<]` → `<`; строки группируются по длине (44, 36, 30) и склеиваются, если детектор разбил одну строку на части.
5. `mrz.parse(lines, { autocorrect: true })` → поля и признак валидности каждого.
6. `mrzToForm()` → начальные значения формы с источником каждого поля.
7. Даты для п. 14 ищутся по всему тексту (см. эвристику выше).

## Проверки перед формированием PDF

- Обязательные поля: 1, 3, 4, 7, 13, 15. Если нажать кнопку без них, PDF не формируется, а незаполненные поля подсвечиваются с подписью. До первого нажатия ошибки не показываются.
- Бланк заполняется латиницей: символы вне WinAnsi (кириллица и т. п.) дают ошибку у поля «Анкета заполняется латиницей».
- Смысловые проверки (предупреждения, не блокируют): паспорт истёк; паспорт действует меньше 3 месяцев после даты выезда (п. 28); паспорт выдан больше 10 лет назад; дата рождения в будущем.

## Формирование PDF

`fillAnketa(values): Promise<Uint8Array>`:

1. Загрузить `anketa-template.pdf`.
2. Для каждого текстового поля — `drawText` шрифтом Helvetica размером из layout. Значение переводится в ЗАГЛАВНЫЕ, кроме e-mail.
3. Для каждой выбранной опции — `drawText('4', ZapfDingbats)` в координатах её квадратика.
4. Вернуть байты. Сохранение: `Blob` → `URL.createObjectURL`.

## Проверка

Vitest, тестовые данные — официальный немецкий образец паспорта (Erika Mustermann, вымышленное лицо), не данные из анкеты:

- `src/lib/pdf.test.ts`: `fillAnketa()` рисует на всех 4 страницах и отказывается от кириллицы;
- `src/lib/mrz.test.ts`: разбор, нормализация `«` и `く`, дата выдачи, проверки `validate()`;
- `src/lib/ocr.test.ts`: склейка распознанных фрагментов в строки.
